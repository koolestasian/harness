---
name: improve
description: Improve a repeated coding/research workflow or compare a prompt, routing rule or model profile using fixed acceptance criteria.
---

Choose one observed failure or repeated task. Read its evidence and reviewed
outcomes. Write one hypothesis, a fixed budget, baseline settings and a rollback
command in docs/research. Compare one change at a time on the same frozen tasks.

Keep evaluation cases, expected sources and acceptance criteria fixed throughout
the comparison. Use separate development examples and held-out tasks. Test memory
supersession, project scope and source fidelity whenever retrieval changes.
The candidate must not edit its own acceptance criteria. Repository rules are
workflow instructions; use process/CI permissions for adversarial isolation.

Measure acceptance, corrections, elapsed time and usage across failures, retries
and review. Unknown usage stays unknown. Do not claim a universal winner from a
few tasks; record the model/provider, task type and applicable limits.

Run the relevant project checks and the workbench's tests after a harness change.
Reject any source-fidelity, isolation or acceptance regression. Save the evidence
as a project finding. Promote a useful procedure to one small SKILL.md under
.agent/skills; load it only for the matching task. Keep the prior version for
rollback. The human orchestrator chooses when to adopt the result.

This is workflow learning with fixed model weights. It is not autonomous
fine-tuning, an always-running optimizer or an independent evaluator.
